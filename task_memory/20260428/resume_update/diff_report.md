## 5. ロール変遷の表現方針（Q2 への論点整理）

LAPRAS のままだと 3Sunny のロールが **4 entry** に分かれている：

```
3Sunny (2023/04 〜 現在)
├── テックリード（フルスタック）   2023/04 〜 2024/08
├── PdMグループ（兼任）           2024/06 〜 2024/12
├── チーフエンジニア              2024/09 〜 現在
└── PdM主務 & 新規事業PJ          2025/01 〜 現在
```

兼任関係があるため、単純な時系列だと重複が分かりづらい。

### 5.1 表現案

#### 案A. ロールごとに別セクション（既存の Repo フォーマットを踏襲、Q2 で本人が想定したパターン）

```
### 株式会社3Sunny (2023/04 ~ 現在)
#### テックリード（フルスタック）   2023/04 ~ 2024/08
#### PdMグループ（兼任）           2024/06 ~ 2024/12
#### チーフエンジニア              2024/09 ~ 現在
#### PdM主務 & 新規事業PJ          2025/01 ~ 現在
```

- ✅ ビズリーチ時代と同じ構造で読みやすい
- ✅ 役割の変遷ストーリーが見える
- ⚠️ 兼任時期があるので「現在」が複数あって読み手が混乱する可能性 → 「兼任」と明記する必要

#### 案B. ストーリー単線型（フェーズ分け）

```
### 株式会社3Sunny (2023/04 ~ 現在)
#### Phase 1: 開発基盤の整備期（2023/04 ~ 2024/08）
#### Phase 2: 組織化期（2024/09 ~ 2024/12）
#### Phase 3: 事業創出期（2025/01 ~ 現在）
```

- ✅ 読み手が会社の中での自分の貢献を時系列で追いやすい
- ✅ 「兼任」を意識せずに済む
- ⚠️ LAPRAS と構造が違うので二重メンテのコストがやや増える

#### 案C. ハイブリッド（推奨）

「現在のロール」を冒頭サマリで先出しし、その下を時系列でフェーズ分け。

```
### 株式会社3Sunny (2023/04 ~ 現在)
- **現職**: PdMグループ（主務）/ チーフエンジニア（兼任）
- **担当領域**: 新規事業開発（PoC〜商品化）/ テックリード / 採用 / 開発プロセス整備
#### 2025/01 ~ 現在: PdM主務として新規事業PJ
#### 2024/09 ~ 現在: チーフエンジニアとして組織横断の技術責任
#### 2023/04 ~ 2024/08: テックリードとして開発基盤・プロセス再構築
```

- ✅ 「いま何をやっている人か」が冒頭で伝わる（短縮版にも転用しやすい）
- ✅ 時系列で深掘りもできる
- ✅ 兼任が明示される

→ 推奨は **案C**。ただし本人の判断による。

## 6. 「強み・弱み」セクションの設計（Q3 への論点）

LAPRAS の `job_summary` には次の素材がある：

### 6.1 LAPRAS から抜粋できる「強み」（本人の自己評価）
- テックリード経験、安定期・グロース期・新規事業フェーズの全段階を経験
- フロント / バックエンド / インフラ網羅
- 開発プロセス改善、CICD 導入、リリース自動化
- 仮説検証、ユーザーインタビュー、PdM としてのプロダクト未来像設計

### 6.2 LAPRAS から抜粋できる「弱み」（本人の自己評価）
- 特定技術のスペシャリストではない（その意思もない）
- ビジョン・戦略学習中
- 高い視座でのエンジニア × ビジネス橋渡しの大規模実績はまだ

### 6.3 ChatGPT 紹介文からの素材（取捨選択が必要）
- 「言葉とコードとチームで未来を描くプロダクトリーダー」← AI 生成感が強いので**そのまま転載しない**
- 採用フロー設計に手を動かす姿勢、論理 × 思いやりのバランス、未来志向 ← **キーワードレベルで抽出可**

### 6.4 採用したい構造
```
## 強み・弱み
### 強み
- フェーズ横断の経験 …
- 採用・育成・プロセス改善まで担う"組織を整えるエンジニア" …
- PdM × エンジニアの橋渡し …
### 弱み（自覚）
- スペシャリストではない …
- 戦略レイヤーは学習中 …
```
